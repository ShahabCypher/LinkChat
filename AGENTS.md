# Project rules

## Committing

Commit as the work lands — after each noticeable change, not once at the end
of a task. Several small commits are the point; one big commit holding
everything is what to avoid. The current `git log` is the style reference.

When a prompt lists multiple tasks (e.g., numbered or bulleted items), give
each task **one or more separate commits of its own** — never bundle multiple
tasks into a single commit.

Message style:

- lowercase, verb-led, no trailing period
- short and specific: what changed, not a story about it
- no prefixes or type tags (`feat:`, `fix:`), no scopes, no issue numbers
- **no attribution of any kind** — never add a `Co-Authored-By` trailer, a
  "Generated with …" line, or any mention of an AI tool, model or agent in the
  message or the body. The message is the change and nothing else.

Good:

```
moved anon helpers into helpers file and added explore button
built explore deck and matching flow
fixed explore actions getting the profile row instead of the id
```

Not good:

```
feat(explore): implement matching flow
Fix row/id mix-up in _flow
Add explore section (generated by an AI agent)
```

The same rule applies to pull request descriptions.

## Building Phases

When implementing a phase from `PROJECT.md` in a new session:

- **Read `PROJECT.md` first**: Treat `PROJECT.md` as the single source of truth for wire formats, UUIDs, cryptography, module boundaries, and exit criteria.
- **Stick to the requested phase**: Implement only the phase asked for (e.g., Phase 1, 2, 3, or 4) plus any tests required to verify it. Avoid speculative features or unrelated refactors.
- **Update status cleanly**: When a phase completes and all checks pass, update the "Project Status" line in `README.md` if needed.

## Architectural Guardrails

- **Keep `core/linkchat_core` pure Python**: Never import `bleak`, `bless`, `customtkinter`, `tkinter`, or Android/Java APIs inside `core/linkchat_core`. It must run identically on Windows CPython 3.12/3.13 and Android Chaquopy using only the Python stdlib and `cryptography`.
- **Keep chunking inside `linkchat_core`**: `ChunkAssembler` lives in `core/linkchat_core`. Platform transports (`WindowsBleTransport`, Kotlin `AndroidBleTransport`, `VirtualTransport`) only pass raw characteristic byte chunks and report negotiated MTU on `on_link_up`. Never duplicate chunking logic in Kotlin or Windows transport code.
- **Inject storage paths**: `LinkChatNode` and `Storage` must take an explicit `data_dir` path (Android passes `context.filesDir`; Windows defaults to a user app-data directory). Never hardcode OS-specific paths in `linkchat_core`.
- **Preserve wire & crypto compatibility**: Never alter packet byte offsets, GATT UUIDs, HKDF salt/info strings, AAD fields, or Ed25519 signature inputs without updating `PROJECT.md` and every platform transport together.
- **Smallest clean implementation**: Prefer small, readable modules and helper functions; handle Windows BLE Peripheral failure gracefully with Central-only fallback rather than crashing.

## Verification

- Run `pytest` after any change to `core/linkchat_core`, `simulator/`, or `tests/`, and ensure all tests pass with no skipped assertions before finishing a phase.
- Verify any new CLI demo or UI entry point imports and launches without syntax or missing-dependency errors.
